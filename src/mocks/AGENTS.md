# src/mocks/ — MSW 목업

BE가 아직 없거나 BE 없이 화면을 만들 때, 그리고 테스트에서 서버 응답을 흉내 낸다.

## 규칙
- `handlers.ts`가 브라우저(`browser.ts`)와 테스트(`server.ts`)에서 **같이** 쓰인다. 핸들러는 기능별 파일(`materialHandlers`·`teachingHandlers`·`battleHandlers`·`rankingHandlers`·`adminHandlers`)에 두고 `handlers.ts`에서 한데 모은다. 다른 곳에서 `http.*`를 등록하지 않는다.
- 목업 데이터는 파일마다 `reset…Data()`로 처음 상태를 만들고 `reset.ts`의 `resetMockData()`가 순서대로 부른다(과목 → 자료 → 가르치기 → 배틀 → 랭킹 → 관리자). 브라우저는 시작할 때, 테스트는 테스트마다, 시연 도구는 "처음 상태로"에서 부른다. 새 데이터 파일을 만들면 여기에 꼭 더한다.
- 경로·필드 이름·에러 모양은 **BE의 Swagger와 똑같이** 맞춘다. 목업이 실제와 다르면 연동할 때 화면이 깨진다.
- 목업 데이터에 실제 학생 정보·실제 강의자료를 넣지 않는다.
- 문제 은행의 실제 문항·정답은 목업에도 넣지 않는다. (학생에게 숨겨야 하는 정보) 끝난 배틀의 복기·관리자 화면에 필요한 예시는 **시안(17~21·25)에 실린 시연 공개 예문만** 쓰고, 진행 중인 배틀 응답에는 싣지 않는다(서버와 같다).
- 배틀 목업은 상태를 물을 때마다 한 걸음씩 진행한다(상대 입장 → 상대 준비 → 풀이 → 완료). 시연 도구의 "배틀 상대 자동 입장·준비"·"다음 배틀 풀이 실패"·"시연 상대의 공개 동의"로 바꾼다. 상대가 만든 대기 방 코드는 `MARI24`다.
- `scenario.ts`: 시연 도구가 바꾸고 핸들러가 읽는 서버 상태(역할·서버 끊김·로그인 만료). `handlers.ts` 맨 앞의 `/api/*` 핸들러가 이를 모든 API에 한꺼번에 적용한다(값을 돌려주지 않으면 다음 핸들러로 넘어간다). 로그인 만료는 **한 번만** 거절해서, 다시 로그인하면 정상으로 돌아온다. 새 시연 상태는 여기에 필드로 더한다.
- `fixtures.ts`: 가짜 사용자 등 목업 데이터. 타입은 `api/generated`에서 가져온다(`features/`를 가져오지 않는다).
- `DemoPanel.tsx`: 시연 도구 패널. 화면을 만들 때 그 화면의 상태(상대 입장·채점 오류 등)를 `scenario.ts`에 더하고 패널에 컨트롤을 한 줄 추가한다.
- 켜고 끄기는 `.env`의 `VITE_USE_MOCK`으로만 한다. 이 값이 `false`면 목업 코드는 실행되지 않는다.
- 서버에 아직 없는 API(`api/pending.ts`)는 목업으로 먼저 만든다. 서버가 올라오면 목업과 실제 응답을 맞춰 본다.
- 시안의 "시연 도구"(상대·오류 상태 흉내 패널)는 이 목업 모드에서만 보여 준다. 실제 서버로 동작할 때는 나오지 않는다.
- 서버가 운영 프로필이면 `dev-login`이 없으므로, 로그인 이후 화면을 혼자 확인할 때는 목업 모드를 쓴다.
