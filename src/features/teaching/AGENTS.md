# features/teaching — 가르치기와 제자 노트  ★ 핵심 화면

## 규칙
- 화면은 시안 08·09대로 **주차 목록(노트 수) + 채팅 + 읽기 전용 노트 패널**이다.
- **노트는 읽기 전용이다.** 노트를 직접 편집·삭제하는 입력창이나 버튼을 만들지 않는다. 고치려면 대화로 다시 말하게 안내한다. 안내 문구는 일상 말투로 쓴다(예: "아까 말한 ○○는 틀렸어, △△야"처럼 말해 보세요). 서버는 번호 명령(`수정 1: …`)을 해석하지 않으므로 그런 안내는 쓰지 않는다. 노트 번호는 화면 표시용이다.
- 노트는 서버가 반영한 것만 보여 준다. 학생이 입력한 말을 FE가 임의로 노트에 미리 넣지 않는다.
- 노트 패널은 **주차별로 묶어서** 보여 주고(T-03), 주차마다 `개수/상한`(예: 12/60)을 표시한다. 개념별 묶음은 만들지 않는다(개념 목록은 학생에게 내려오지 않는다). 상한이 차면(`noteLimitReached`) "노트가 가득 찼어요. 새 노트만 못 들어가고, 기존 노트를 고치거나 지우는 것은 대화로 할 수 있어요"를 안내한다.
- 서버가 노트 변경을 일부 반려한 경우(`rejectedCount`)에는 "이 부분은 노트에 담기지 않았어요. 더 구체적으로 설명해 보세요"처럼 **설명을 보완하도록** 안내한다.
- 비슷한 노트는 서버가 정리한다: 유사도 ≥0.9는 자동 병합(`merged`)되어 표시만 하고, 0.75~0.9(`mergeSuggestions`)는 **채팅 안, 제자 답 바로 아래의 확인 카드**로 "합칠까요?"를 묻는다. 합치기는 T-05(서버에 없으면 목업, `api/pending.ts`), 무시하면 카드가 사라진다. 모순 질문·알림은 없다.
- AI 응답은 몇 초 걸린다. 전송 중 상태(로딩, 중복 전송 방지)와 실패 시 재전송을 반드시 만든다. 메시지마다 `clientMessageId`(UUID)를 만들어 보내고, `AI_UNAVAILABLE`·`AI_RATE_LIMITED`·`AI_BAD_RESPONSE`는 아무것도 저장되지 않으므로 **같은 id로 다시 보내도 된다**. 동시에 두 번 보내 겹치면 `TEACHING_CONCURRENT_TURN`.
- 붙여넣기는 두 가지다. (1) 입력창에 붙여넣는 순간 FE가 간단한 안내만 띄운다(서버 판정과 무관, 전송은 막지 않는다). (2) 전송 뒤 응답의 `pasteWarning=true`면 복붙 경고를 보여 준다. 둘 다 복사율 같은 수치는 보여 주지 않고 전송을 막지 않는다. 지시문 의심 입력 안내는 없다(채점 때만).
- 제자의 되묻는 질문(`askedWhy`)은 학생이 다음 입력을 하기 쉽도록 입력창 가까이에 보이게 한다.
- 대화 내용은 개인정보가 될 수 있으니 콘솔에 출력하지 않는다.
