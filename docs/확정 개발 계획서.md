### 단계 1. 공통 기반
- 라우터와 **가드**(로그인 전 접근 차단, 관리자 전용), 401 처리는 `api/client.ts` interceptor 한 곳, `authStore`(localStorage 한 키), 에러 코드 → 한국어 문구 표(`api-spec.md` 12절).
- 앱 틀을 시안 구조로 확정: 헤더 + 왼쪽 메뉴(과목 선택 ⌄ + 과목 홈·가르치기·학습 자료·제자 배틀·배틀 기록·과목 랭킹·내 정보·운영·문제 점검(관리자만)) + 본문 + 하단 줄. 로그인 전 틀(1200px).
- **폴링 훅**(간격 2~3초, 끝 상태에서 멈춤: 배틀은 `FINISHED`·`CANCELED`·`EXPIRED`, `ERROR`에서는 계속, 자료는 `DONE`·`FAILED`), AI 호출이 걸린 요청의 긴 `timeout`.
- MSW: 기본 핸들러·사용자 시나리오 틀, 개발 모드에서만 보이는 **시연 도구 패널**(상대·오류 상태 흉내).
- **끝났다는 기준**: 로그인 전/후 틀이 뜨고, 가드·401·에러 문구·폴링 훅이 단위 테스트를 통과한다.

### 단계 2. 로그인·가입 (시안 01·02·03)
- 01 랜딩 → 02 Google 로그인(개발 중엔 `dev-login`, 마지막에 실제 Google) → 처음이면 03 닉네임·학과(선택 상자, 학과는 A-05)·약관 → 내 과목.
- 오류: `AUTH_EMAIL_DOMAIN_NOT_ALLOWED`, `AUTH_GOOGLE_TOKEN_INVALID`, 닉네임 중복·형식, 약관 미동의.
- **끝났다는 기준**: 가입 → 재접속 → JWT 만료(401) 뒤 재로그인까지 시나리오 테스트 통과, 학교 계정이 아닐 때 안내 표시.

### 단계 3. 과목·제자·주차 (시안 04·05·06·07·08)
- 04 내 과목, 06 새 과목 만들기(이름 → 기존 과목 검색 → 선택·새로 만들기, 학기 자동, `COURSE_DUPLICATE`는 기존 과목으로 이동), 07 제자 만들기(이름·모습), 05 과목 홈(제자 카드·Elo·주차 목록·노트 수), 08 주차 만들기(같은 이름이면 기존 주차).
- 시안의 "4개 주차" 표기는 C-03에 `unitCount`가 없어 우선 C-05를 과목마다 불러 채운다(BE 변경 요청서 참고).
- **끝났다는 기준**: 과목 만들기 → 제자 만들기 → 주차 만들기까지 실제 서버로 동작, 제자가 없는 과목에서 가르치기·배틀 진입이 막힌다.

### 단계 4. 자료 (시안 10·11)
- 10 자료 목록·추가(PDF 또는 붙여넣기, 권한 동의 체크가 켜져야 저장), 처리 상태 폴링(`PENDING`→`PROCESSING`→`DONE`·`FAILED` 이유 표시), 11 여러 주차에 연결(M-06).
- 시안의 "문제 24개"는 API가 문항 수를 내려주지 않으므로 표시하지 않는다(처리 상태·연결된 주차만).
- 삭제 버튼(M-05)은 BE 구현 전까지 숨긴다.
- **끝났다는 기준**: 공개 자료로 업로드 → `DONE` → 주차 연결, 파일·크기·동의 오류 문구, 스캔 PDF `NO_TEXT` 안내.

### 단계 5. 가르치기 (시안 08·09) — 핵심 화면
- 왼쪽 주차 목록(노트 수) + 가운데 채팅 + 오른쪽 **읽기 전용** 노트 패널(주차별, `12/60`), Enter 전송·Shift+Enter 줄바꿈.
- 전송 중·중복 전송 방지(`clientMessageId`)·실패 재시도(`AI_*` 오류는 같은 id로 재전송), 제자의 되묻기, 일부 반려 안내(`rejectedCount`), 노트 가득 참(`noteLimitReached`), 붙여넣기 안내(FE)와 복붙 경고(`pasteWarning`), 자동 병합 표시, **병합 확인 카드(채팅 안)**.
- 노트 수정·삭제 안내는 일상 말투("아까 말한 ○○는 틀렸어, △△야"처럼). 노트 번호는 표시용.
- 노트에 편집·삭제 버튼을 만들지 않는다.
- **끝났다는 기준**: 같은 메시지를 두 번 보내도 한 번만 반영되고, 노트가 쌓이며, 3의 배수 턴에 되묻기가 나온다. T-04·T-05는 BE 구현 전까지 목업으로 화면만 완성.

### 단계 6. 배틀 (시안 12~16)
- 12 방 만들기(주차·문제 수 3~10·`내 노트 N개 · 내가 안 본 문제 M개`·공개 동의 체크) / 방 코드 입장 / **`/join/코드` 링크 입장**, 대기실(방 코드·만료 시각·준비 완료·**참가자 누구나 취소**), 15 풀이·채점 중, 16 오류(다시 시도 / 포기하고 나가기), 만료·취소 화면.
- 폴링: `FINISHED`·`CANCELED`·`EXPIRED`에서 멈추고 `ERROR`에서는 계속(상대가 재시도하면 따라간다). 새로고침해도 방으로 복귀.
- 오류 코드별 안내: `BATTLE_NOTES_REQUIRED`(가르치러 가기), `BATTLE_QUESTION_BANK_NOT_READY`, `BATTLE_NOT_ENOUGH_QUESTIONS`(로비에 머물고 준비 해제), `BATTLE_ROOM_*`, `BATTLE_ALREADY_ACTIVE`, 연타 방지(준비는 멱등).
- 진행 중 화면에 문항·정답·상대 노트를 내리지 않는다.
- **끝났다는 기준**: **브라우저 두 개(두 계정)** 로 방 만들기 → 입장 → 준비 → 결과까지, 취소·만료·ERROR 복구 시나리오 통과.

### 단계 7. 결과·복기·연습 (시안 17·18·19·21)
- 17 결과 + 복기(정답 숨김, 문항별 제자의 답·사용한 노트·복붙 계수·원인 제안, **원인 5종 선택**, 메모, 신고 R-03), **정답 보기**(되돌릴 수 없음 확인 창 → R-11) 뒤 3칸(모범 답·자료 근거) 표시, 틀린 문항 미리 체크·맞힌 문항 선택 → **연습 배틀**(B-10) 시작·폴링·18 연습 결과("이전 답 → 이번 결과", 정답 없음, 랭킹 미반영, 다시 연습 버튼 없음).
- 채점 조작 의심 문항은 배지만 보이고 패턴은 보이지 않는다.
- **끝났다는 기준**: 정답 보기 전 응답·화면에 모범 답·근거가 없음을 확인(네트워크 응답 포함), 연습이 랭킹에 반영되지 않음, 정답을 연 뒤 연습 시작이 막힘(`PRACTICE_ANSWERS_REVEALED`).

### 단계 8. 기록·랭킹·내 정보 (시안 22·23·24)
- 22 배틀·연습 기록(B-06), 23 과목 Elo 순위·내 순위·성장폭(7일)·상대별 전적·상대별 배틀 목록(K-04)·Elo 변동 이력(K-07), 24 닉네임·학과 수정(A-07)·로그아웃(토큰 삭제).
- 시안 22의 "연습 1회 · 정답 공개"·"0 : 0"은 B-06에 필드가 없어 BE 변경 요청서의 해당 항목이 반영될 때까지 단순 표시로 둔다.
- **끝났다는 기준**: 배틀 뒤 Elo 변동이 기록·랭킹에 나타난다.

### 단계 9. 노트 교환 리뷰 (시안 20)
- 양쪽 모두 공개 동의했을 때만 서로의 노트를 나란히 보고 좋았던 점·보완점 작성(R-06~R-08). 공개 동의 변경(B-08)은 17·20에서.

### 단계 10. 관리자 (시안 25)

### 단계 11. 마감·연동
1. **Google 실로그인 연결**(dev-login → Google ID 토큰 흐름), 학교 도메인 검사 오류 문구 확인.
2. **모든 화면 상태 4종**(로딩·에러·빈·정상) 점검, 404.

## 5. 단계마다 반복하는 작업 단위

1. **시안 확인**: 해당 화면을 Figma에서 읽고, 없는 상태는 추가 시안을 그려 사용자 확인.
2. **API 확인**: Swagger 타입과 `api-spec.md` 비교, 없는 API는 `TODO(BE)`와 목업.
3. **MSW 핸들러**(같은 경로·필드·오류 모양) → **훅**(`useQuery`/`useMutation`, `fetch` 직접 사용 금지) → **컴포넌트**(`components/ui` 재사용) → **페이지**.
4. **상태 4종 + 화면별 추가 상태**, 오류는 `ApiError.code`로 분기.
5. **테스트**(사용자가 보는 글자·역할 기준) → `npm run typecheck && npm run lint && npm test`.
6. **브라우저 확인**: 개발 서버를 띄워 시안과 나란히 비교(AI가 브라우저로 확인). 서버에 dev-login이 없어서 AI의 확인은 **MSW 모드**로 하고, 실제 서버 확인은 로그인을 사용자가 해 준 상태에서 한다.
7. **커밋**: `feat/<단계>-<이름>` 브랜치, 커밋 메시지 `feat:` 형식, 끝에 AI 사용 한 줄. push·PR은 사용자.

## 7. 진행 방식과 역할

고정된 역할 분담 없이 **번갈아 진행**한다. 사용자가 "몇 번째 진행할 차례"라고 알려 주면 그 차례의 단계(4절)를 한다.

| 누가 | 하는 일 |
|---|---|
| AI | **알려 준 단계만** 진행: FE 구현·테스트·Figma 추가 시안·문서, 커밋은 `feat/` 브랜치까지. 단계를 끝내면 결과·남은 것·다음 단계에서 필요한 것을 알린다. 알려 주지 않은 다음 단계로 먼저 넘어가지 않는다 |
| 차례를 맡은 사람 | 그 단계의 지시·확인·승인(추가 시안 확인 포함), push·PR·병합 |
| 사용자 | 차례 알림, BE 변경(BE_변경_요청서 기준), 열어 둔 서버·Google 설정 |

- 차례는 단계 번호로 부른다(예: "단계 2 차례야"). 한 차례에 여러 단계를 부탁하면 그대로 이어서 한다.
- 단계마다 사용자 확인이 필요한 것(추가 시안, 규칙 파일 수정, 약관 문구)은 그 차례 안에 묻는다.
