# 단계 2·3 구현 기록

2026-11-12 · 작업 브랜치 `feat/2-3-auth-courses` · 기준 `origin/develop`

## 구현

- 단계 2: 랜딩, 학교 Google 로그인, 신규 가입(닉네임 중복 확인·학과 선택·필수 동의), 가입 토큰 만료 안내, 로그인 오류, 로그인 뒤 원래 주소 복귀.
- Google 클라이언트 ID는 사용자에게 받아 커밋되지 않는 `.env`에 설정했다. ID 토큰은 로그인 요청에만 사용한다. 액세스 토큰은 기존 `mari.accessToken` 키에 저장한다.
- 가입 토큰은 React Context의 메모리에만 보관하고 가입 화면을 떠나면 지운다. 새로고침하면 다시 로그인한다.
- 단계 3: 내 과목, 기존 과목 검색과 참여 확인, 새 과목, 제자 만들기, 과목 홈, 주차 만들기, 주차별 내 노트 수, Elo, 과목 선택 및 마지막 과목 기억.
- 과목·주차 중복 오류의 `details.existingCourseId`·`details.existingUnitId`를 보존해 기존 항목으로 이동한다. 다른 탭에서 제자를 먼저 만든 경우 최신 제자를 다시 조회한다.
- 제자 없는 과목은 가르치기·배틀 주소 직접 접근도 차단한다. 가르치기·배틀 기능 화면 자체는 후속 단계의 기존 자리표시를 유지했다.
- 같은 API·필드 모양의 MSW 핸들러와 가짜 과목·제자·주차 데이터를 추가했다. 목업 데이터는 새로고침하면 초기화된다.

## 시안과 자료

- 사용자가 제공한 `figma-laptop.html`의 01~08 화면을 기준으로 구조·문구를 구현하고 기존 디자인 토큰·공통 부품을 재사용했다.
- 가입 약관·Google 로그인 오류·기존 과목 검색·참여 확인의 HTML 추가 시안은 사용자 승인 후 구현했다. Figma 원본 파일에는 반영하지 않았다.
- 이미지 생성 AI로 만든 기존 마리 그림 2개를 사용자가 제공한 프로토타입에서 가져와 WebP로 변환했다(약 266KB 합계). 외부 이미지 URL을 런타임에 호출하지 않는다.
- Google 로그인 연결은 [Google Identity Services 공식 문서](https://developers.google.com/identity/gsi/web/reference/js-reference)를 참고했다.
- 실제 서버의 `/v3/api-docs`에서 2·3단계에 사용하는 경로와 요청·응답 필드가 기존 생성 타입과 일치하는 것을 확인했다.

## 검증 결과와 남은 확인

- 타입 검사·린트·배포 빌드 통과. 테스트 17개 파일, 132개 통과.
- 신규 검증: 가입과 동의, 닉네임 중복, 가입 토큰 만료, 로그인 뒤 원래 주소 복귀, 로그인 유지, 학교 외 계정 거절, Google ID 토큰 전달 및 스크립트 로딩 재시도, 과목→제자→주차 흐름, 기존 과목 참여, 과목 중복, 다른 탭의 제자 생성, 주차 중복, 제자 없는 과목 차단, 검색 실패·빈 상태, 과목 기억, 한국 시간의 학기 경계.
- **미완료 검증**: 브라우저 자동화 연결 실패로 화면의 시각적 대조·브라우저 조작 검증을 완료하지 못했다. 실제 Google 로그인과 실제 서버에서 과목·제자·주차 생성도 사용자가 직접 로그인한 뒤 확인해야 한다. 따라서 계획서의 단계 2·3 전체 완료 기준을 충족했다고 표시하지 않는다.
- Google OAuth의 승인된 JavaScript 출처에는 실제 사용하는 FE 주소(`http://localhost:5173`)가 등록돼 있어야 한다.
- 이용 안내 최종 약관 문구는 계획서대로 팀 검토가 남아 있다.

## 확인 방법

실제 서버는 `npm run dev`로 실행하고 `/login`에서 학교 Google 계정으로 로그인한다. Google 설정을 바꿨다면 개발 서버를 다시 실행한다. 목업은 `VITE_USE_MOCK=true`인 `.env.mock`을 두고 `npm run dev -- --mode mock --port 5174`로 실행한다. 로그인 화면의 목업 버튼으로 기존 사용자·신규 가입·학교 외 계정 오류를 확인할 수 있다.
