## 구현

- **서버**: 주소가 `https://audit-challenging-wma-ted.trycloudflare.com`으로 바뀌어 Swagger(경로 52개)로 타입을 다시 만들었다. T-05·R-06·R-07·R-08이 올라와 실제 타입으로 연결했다. T-04·M-05·R-10은 아직 없다.
- **자료(10·11)**: PDF·붙여넣기 업로드, 올리기 전 파일 검사, 처리 상태 따라가기, 실패 이유, 주차 연결, 삭제(서버에 없으면 안내).
- **가르치기(09)**: 주차 목록 + 채팅 + 읽기 전용 노트(`개수/상한`). Enter 전송·Shift+Enter 줄바꿈, 같은 `clientMessageId`로 재전송, 병합 확인 카드(채팅 안, T-05), 노트 가득 참·일부 반려·붙여넣기 안내, 되묻는 질문을 입력창 가까이에 표시.
- **배틀(12~16)**: 내 노트 수·안 본 문제 수 안내, 노트 0개 주차는 방 만들기 차단, 진행 중인 방 이어가기, 코드·링크 입장(`/join/코드`), 코드·링크 복사, 준비 완료 때 공개 동의 전송, 상태 7가지 화면, 오류에서 다시 시도·포기.
- **복기·연습(17~19·21)**: 점수·Elo, 문항별 제자 답·사용한 노트, 원인 제안과 직접 선택 5종, 메모·출처·이유, 정답 보기 확인 창, 틀린 문제 기본 선택 → 연습 → 연습 결과(이전 판정과 비교), 문제·채점 신고.
- **노트 교환 리뷰(20)**: 공개 동의 변경(B-08), 상대 노트, 좋았던 점·보완할 점·근거 노트, 배틀당 1회.
- **기록·랭킹·내 정보(22~24)**: 종류별 기록과 상태에 맞는 이동, Elo 순위·내 순위·성장폭 7일·상대별 전적과 배틀 목록·Elo 변동, 닉네임·학과 수정과 로그아웃.
- **관리자(25)**: 문항 목록·상세·상태 변경, 직접 추가, 주차별 문제 만들기 작업, 신고 처리, 사용 통계·AI 호출 수·살펴볼 문항, CSV 내보내기.
- 모든 라우트가 실제 화면이 되어 임시 자리표시(`ComingSoonPage`)를 지웠다.

## 시안·명세와 다르게 한 것

- **Figma에 먼저 그리지 않고 만든 상태**: 자료 처리 중·실패, 병합 확인 카드, 재전송 안내, 대기실의 준비 전(공개 동의 체크)·만료·취소, 정답 보기 확인 창, 빈 상태들. 이미 승인된 공통 부품(`StateBox`·`Dialog`·`Card`·`Toast`)만으로 만들었다. 규칙(시안에 없는 화면은 Figma 먼저)과 다르므로 모양을 확인받아야 한다.
- **서버에 값이 없어 뺀 것**: 자료의 문제 수, 대기실의 제자 이름·확정 노트 수(닉네임으로 표시), 복기 머리말의 날짜, 연습 결과의 이전 답 문장(판정만), "나의 배틀 노트", 기록의 상대 점수·연습 횟수·정답 공개 표시. 요청은 `BE_변경_요청서.md` C절.
- **넣지 않은 것**: 노트 이력(T-04)·복기 기록 모아 보기(R-10) — 서버에 없고 응답 모양도 정해지지 않았다. 관리자의 "미판정 문항 사용" 스위치(팀 결정).
- **Swagger 타입 충돌**: 복기·문항 정답률·성장폭 응답은 Swagger가 틀리게 나와 `src/api/overrides.ts` 등에 BE DTO 그대로 적었다.

## 검증 결과와 남은 확인

- 타입 검사·린트·배포 빌드 통과. 테스트 24개 파일, 188개 통과.
- 목업 모드 브라우저(1440px)에서 자료·가르치기·배틀·복기·기록·랭킹·내 정보 화면이 열리고 가로 넘침이 없는 것, 방 만들기 → 상대 입장 → 준비 완료 → 풀이·채점 → 복기까지 이어지는 것을 확인했다.
- 새 서버에는 읽기 전용 요청(health·Swagger)만 보냈다.
- **미완료 검증**: 실제 서버에서 Google 로그인 뒤의 흐름 전체, 두 계정으로 하는 배틀, 실제 AI 응답 시간에서의 가르치기·풀이, 관리자 계정 화면, 시안과의 픽셀 단위 대조. 계획서 단계 6의 "브라우저 두 개(두 계정)" 기준은 충족하지 않았다.
